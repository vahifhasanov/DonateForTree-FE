# Аудит виправлення карти — лабораторна №6

## Виправлення

Нова база `mock/seed.json` має порожній `trees`. Реєстрація не створює посадок.
Старий набір збережено лише як маніфест міграції та тестові приклади, він не додається до API.
Міграція видаляє лише повні збіги старих записів без requestKey. Змінені записи та створені POST
зберігаються. Перед видаленням створюється локальна резервна копія; повторний запуск безпечний.
У робочій базі прибрано 6 seed-груп, збережено 1 POST-посадку (1 дерево) та всі акаунти.
Локальні дані й резервна копія ігноруються Git.

Координати нових посадок беруться із трьох визначених точок для кожної області.
Для Київської області використано точки поза містом Київ. Випадкового зміщення немає.
Збіги координат об'єднуються в один маркер із сумою кількостей і popup усіх записів.
Фільтри застосовуються перед групуванням. Координати умовні, не підтверджені місця посадки.

## Перевірені рівні

- Vitest: 46 тестів, 5 файлів. Справжній тимчасовий HTTP API: порожній старт, реєстрація,
  POST, owner на сервері, сума, повторний ключ, особиста колекція двох власників, спільний GET,
  фільтри/статистика, перезапуск, відхилення старого токена, повторний вхід та збереження даних.
- Міграція: резервна копія, збереження акаунтів/POST/змінених записів, ідемпотентність.
- Code review: useAuth/Context; useTrees/useMyTrees з AbortController і захистом від старого
  власника; usePlantTree/useMutation з блокуванням і ключем повтору; useTreeFilters без запитів
  при кожному фільтрі. Нескінченних залежностей у ефектах не виявлено.
- Захист маршрутів /plant і /trees, повернення після входу, помилки HTTP, JSON і мережі
  реалізовані. Статистика використовує quantity та total, без штучних таймерів.
- Cypress не виконав тести: процес завершується до запуску (Windows/GPU, профіль середовища).
  Успішний E2E не заявляється. Раніше доступ Chrome через UI також не надано.

## Ручний сценарій (обов'язково перед PR)

1. Відкрити http://127.0.0.1:5174. Уже запущені Vite/API не запускати вдруге.
2. GET http://127.0.0.1:3001/trees має показати збережені POST-посадки, без ID 2351–2356.
   У чинній базі одна користувацька посадка — це очікувано; не очищати її заради порожньої карти.
3. Зареєструвати вигаданий акаунт A. Перейти /trees: 0 дерев, 0 UAH, порожня колекція.
4. /map показує тільки посадки, які вже є в GET /trees. Для повністю нової окремої бази
   карта порожня (це перевірено HTTP-тестом); основну базу не видаляти.
5. /plant: 5 дерев, Maple, Lviv. Перевірити 750 UAH, Review, Confirm demo planting.
   У Network має бути POST /trees зі статусом 201, кількістю 5 і owner поточного акаунта.
6. /trees: одна група, 5 дерев, 750 UAH. Reload зберігає результат.
7. View on map: popup потрібної посадки у Львівській області, атрибуція OpenStreetMap.
8. Перевірити drag, колесо, +/−, клавіатуру, пошук Lviv/Maple, область, породу, рік,
   нуль результатів і Reset filters. Вибраний запис може бути прихований фільтрами — є пояснення.
9. Створити ще кілька груп у тій самій області: збіги точок мають один маркер із сумою;
   popup має містити дані всіх груп, жодна посадка не губиться.
10. Вийти і ввійти A: колекція та статистика збережені. Зареєструвати B:
    /trees порожня, але /map показує посадки A та інших. Створити посадку B, перевірити
    особисті колекції A/B окремо й обидві посадки у загальному GET та на карті.
11. При перезапуску лише API дані зберігаються, потрібен повторний вхід (сесії в пам'яті).
12. DevTools Console — без помилок; Network — успішні Leaflet JS/CSS і тайли OSM.
    Без інтернету очікується повідомлення про недоступність карти/тайлів і кнопка Retry.
13. На ширинах 320, 390, 768, 1440 перевірити меню, форми, popup, відсутність прокрутки по горизонталі.
14. Перевірити некоректну суму (151), 0/101 дерев, невірний пароль, повторний email,
    різні підтвердження пароля; записи не повинні створюватися при помилці.

## Обмеження та готовність

Фінальні команди: `npm run lint`, `npm run test:unit` (46/46), `npm run build`,
`npm run format:check` та `git diff --check` завершились успішно.
Чинний API повертає 1 збережену POST-групу / 1 дерево, жодного старого seed-ID;
frontend `/map` відповідає HTTP 200. Це перевірка HTTP, а не візуального відображення.

API локальний, один процес на JSON-файл, синхронний запис; навчальна авторизація, без платежів.
Після зміни mock/server.js потрібен перезапуск тільки API. CDN/тайли потребують інтернету.
Зміни підготовлені до рев'ю; критичні візуальні перевірки вище ще не підтверджені.
Не вважати лабораторну повністю перевіреною до проходження ручного сценарію або Cypress.
Commit/push/PR/merge не виконані.
