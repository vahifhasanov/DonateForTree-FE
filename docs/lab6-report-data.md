# Дані для Word-звіту з лабораторної роботи №6

## 1. Тема роботи

«Реалізація фронтенд частини. Ч3 — бізнес-логіка».

## 2. Мета роботи

Реалізувати бізнес-логіку власного React-проєкту, отримання і надсилання даних
через HTTP та користувацький хук авторизації.

## 3. Використані технології

React 19, Vite 8, React Router 7, JavaScript, fetch, React Context, CSS Modules,
Leaflet 1.9.4, OpenStreetMap, Node.js, Vitest, Cypress, ESLint і Prettier.
Локальний навчальний API використовує вбудовані модулі Node.js без серверного фреймворку.
TanStack Query не застосовано: для обсягу роботи достатньо власних хуків.

## 4. Короткий опис проєкту

DonateForTree — навчальний застосунок для демонстраційного висаджування дерев
в областях України. Користувач обирає параметри посадки, зберігає запис і переглядає
особисту колекцію та загальну карту. Справжня оплата та фізична посадка не виконуються.

## 5. Реалізована бізнес-логіка

Вартість одного дерева — 150 UAH, допустима кількість — від 1 до 100 цілих дерев.
Можна вибрати готову кількість або власну суму, кратну 150 UAH, породу та область.
Перед POST користувач перевіряє вибір і підтверджує демонстраційну посадку.
API сам визначає власника за токеном, дату, координати і загальну суму.
Кнопка блокується під час запиту, а Idempotency-Key запобігає повторному створенню запису.

Нова база посадок порожня. Реєстрація не додає дерев. У загальній карті є лише збережені
посадки користувачів; особиста колекція містить записи поточного власника.
Статистика підсумовує кількість дерев, суми та число областей за записами API.
Одна посадка може містити групу дерев. Записи зберігаються у локальному JSON-файлі,
який не включається до Git. Перезавантаження сторінки та повторний вхід не видаляють дані.
Міграція прибирає тільки точні збіги старих seed-записів із попередньою резервною копією.

## 6. Інтерактивна карта

Leaflet відображає підкладку OpenStreetMap з атрибуцією. Реалізовано переміщення,
масштабування, маркери, popup, пошук за ID, породою, областю або містом,
фільтри області, породи й року та скидання фільтрів. Є повідомлення про відсутність результатів.
Посилання з TreeCard відкриває відповідну посадку через `/map?tree=ID`.

Координати обираються з визначених демонстраційних точок усередині відповідної області.
Вони не є підтвердженими місцями фактичних посадок. Збіги координат об'єднуються в маркер
із загальною кількістю дерев; popup містить відомості про всі посадки цієї точки.
Leaflet JS/CSS завантажуються з CDN unpkg з фіксованою версією і перевіркою SRI.
Для карти потрібен інтернет; передбачено повідомлення про помилки бібліотеки та тайлів.

## 7. Авторизація та реєстрація

Використано наявні сторінки входу й реєстрації. Перевіряються ім'я, email, довжина пароля,
повторний пароль і зайнятість email. Mock API хешує паролі через scrypt із випадковою сіллю.
Браузер зберігає токен у localStorage; користувач перевіряється GET `/auth/me`.
Сесія діє до 24 годин, вихід відкликає токен. Після перезапуску API потрібно ввійти знову,
оскільки сесії зберігаються в пам'яті; облікові записи та посадки залишаються на диску.
Маршрути `/trees` і `/plant` захищені. Після входу відновлюється запитаний маршрут.
Це локальна навчальна авторизація, яка не заявляється як production-безпечна система.
Використовуються лише вигадані дані та навчальні паролі.

## 8. Власні React-хуки

| Хук            | Призначення                                                                          | Файл                          |
| -------------- | ------------------------------------------------------------------------------------ | ----------------------------- |
| useAuth        | Доступ до користувача, входу/реєстрації, виходу та відновлення сесії через Context   | `src/hooks/useAuth.js`        |
| useTrees       | Завантаження загальних посадок, loading/error, повторний GET і скасування запиту     | `src/hooks/useTrees.js`       |
| useMyTrees     | Завантаження лише особистої колекції через useTrees(true)                            | `src/hooks/useTrees.js`       |
| usePlantTree   | Валідація, створення посадки, ключ повторного запиту та повідомлення про зміну даних | `src/hooks/usePlantTree.js`   |
| useMutation    | Стани loading/error/data, блокування одночасних операцій, скидання результату        | `src/hooks/useMutation.js`    |
| useTreeFilters | Пошук, комбіновані фільтри, список років і скидання                                  | `src/hooks/useTreeFilters.js` |

Реалізація сесії розташована в `src/context/AuthProvider.jsx`; HTTP-запити відокремлені
від компонентів у `src/api`. Запити читання використовують AbortController.

## 9. Фрагменти реального коду GET та POST

Файл `src/api/trees.js`, отримання загальної або особистої колекції:

```js
const data = await request(mine ? '/my-trees' : '/trees', {
  signal,
  authenticated: mine,
})
```

Той самий файл, створення посадки:

```js
const data = await request('/trees', {
  method: 'POST',
  body: payload,
  authenticated: true,
  headers: { 'Idempotency-Key': requestKey },
})
```

`payload` містить quantity, species та region. Функція request у `src/api/client.js`
виконує справжній fetch, перетворює тіло в JSON, додає Bearer-токен,
обробляє HTTP/мережеві помилки, порожню відповідь і timeout.
Адреса API задається `VITE_API_URL`, стандартно `http://127.0.0.1:3001`.

## 10. Структура проєкту

- `src/api/` — HTTP-клієнт, операції авторизації й посадок.
- `src/hooks/` — користувацькі хуки.
- `src/context/` — стан авторизації.
- `src/components/` — спільні елементи, TreeCard, TreeMap, фільтри та захист маршрутів.
- `src/pages/` — головна, карта, колекція, посадка, форми входу/реєстрації, 404.
- `src/utils/` — правила, статистика, фільтрація, координати й завантаження Leaflet.
- `mock/` — локальний API, порожній seed і безпечна міграція старих даних.
- `src/tests/`, `cypress/` — автоматичні перевірки.
- `docs/` — матеріали звіту, аудит і ручний сценарій перевірки.

## 11. Результати тестування

Фінально виконано `npm run lint`, `npm run test:unit`, `npm run build`.
Vitest: **46 успішних тестів у 5 файлах**. Перевірено правила кількості й вартості,
фільтри, HTTP-помилки, справжні GET/POST до тимчасового API, порожню нову базу,
реєстрацію/вхід/вихід, власника посадки, ізоляцію двох акаунтів, статистику,
повторний POST, збереження після перезапуску та безпечну міграцію.
ESLint і production build завершилися успішно.
`npm run format:check` і `git diff --check` також завершилися успішно.

Cypress-сценарії підготовлені, але виконання E2E у поточному середовищі не підтверджене:
процес Cypress завершується до тестів через обмеження Windows/GPU/профілю.
Візуальну роботу карти, drag/zoom, адаптивність і відсутність помилок консолі
потрібно перевірити у браузері користувача за `docs/lab6-audit.md`.
Успішне браузерне тестування не заявляється.

## 12. Висновок

У проєкті реалізовано бізнес-логіку демонстраційної посадки, HTTP-обмін даними,
власні React-хуки та авторизацію. Особиста колекція відокремлена за власником,
загальна карта використовує збережені посадки всіх користувачів.
Автоматичні перевірки логіки й API та production-збірка успішні.
Повна перевірка інтерфейсу потребує завершення ручного браузерного сценарію.

## Рекомендовані скриншоти

1. Головна сторінка: композиція з деревом, навігація та лічильник із даних API.
2. Реєстрація: поля й помилка різних паролів; без справжніх персональних даних.
3. Нова особиста колекція: порожній список, 0 дерев та 0 UAH.
4. Форма посадки: кількість, порода, область і розрахована сума.
5. Перевірка вибору та повідомлення про збереження без справжньої оплати.
6. Особиста колекція після reload: нова картка та відповідна статистика.
7. Карта: маркер у вибраній області, відкритий popup та атрибуція OpenStreetMap.
8. Карта з фільтрами та порожнім результатом; окремо результат після скидання.
9. Другий акаунт: порожня особиста колекція за наявності посадок першого на загальній карті.
10. DevTools Network: успішні GET та POST; приховати токени й заголовок Authorization.
11. Термінал: ESLint, 46/46 Vitest, build і перевірка форматування.
12. Мобільний вигляд форми та карти без горизонтального переповнення.
