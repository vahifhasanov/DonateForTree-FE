# Матеріали лабораторної роботи №6

Це окремий зміст для перенесення у шаблон викладача. Шаблон звіту не знайдений.

## Мета роботи

Реалізувати бізнес-логіку DonateForTree, обмін даними через HTTP та власні React-хуки.

## Використані технології

React 19, Vite 8, React Router 7, fetch, Context, Leaflet 1.9.4, OpenStreetMap,
вбудований HTTP API Node.js, Vitest, Cypress, ESLint, CSS Modules.

## Бізнес-логіка

Вибір кількості/суми, породи та області; 150 UAH за дерево; 1–100 дерев.
Перевірка параметрів, перегляд вибору, демонстраційне підтвердження без платежу.
POST створює групу з власником, датою та умовними координатами. Повторна відправка захищена
блокуванням кнопки та Idempotency-Key. Колекція, карта й статистика читають збережені дані.

## Власні хуки

- useAuth — користувач, вхід, реєстрація через login(credentials, true), вихід, відновлення сесії.
- useTrees / useMyTrees — GET, loading/error, повторне завантаження, AbortController.
- usePlantTree — валідація, POST та сповіщення про зміну даних.
- useMutation — pending/error/success та захист від одночасної відправки.
- useTreeFilters — пошук, область, порода, рік і скидання без додаткових HTTP-запитів.

## Приклади GET та POST

```js
fetch('http://127.0.0.1:3001/trees')
fetch('http://127.0.0.1:3001/trees', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`,
    'Idempotency-Key': crypto.randomUUID(),
  },
  body: JSON.stringify({ quantity: 5, species: 'Maple', region: 'lviv' }),
})
```

Токен отримується POST /auth/login або /auth/register, не зберігається в Git.

## Інтерактивна карта

Leaflet + OpenStreetMap, справжні географічні координати умовних демонстраційних точок.
Переміщення, zoom, popup з породою, областю, датою, кількістю та сумою.
Пошук і комбіновані фільтри змінюють маркери; порожній результат пояснюється текстом.
Перехід із TreeCard відкриває потрібну точку. Є атрибуція та обробка збоїв CDN/тайлів.

## Авторизація

Локальна навчальна система: перевірка email/пароля/імені, підтвердження пароля у формі,
scrypt на mock API, Bearer-сесія, захищені маршрути, вихід. Токен переживає оновлення сторінки,
але після перезапуску API потрібно увійти повторно. Лише вигадані дані; production-безпека не заявляється.

## Результати тестування

Vitest: 46 успішні тести, включно зі справжніми GET/POST, реєстрацією/входом/виходом,
перевіркою власника, помилок, дублікатів і збереженням даних після перезапуску API.
Production build успішний. ESLint перевірено після виправлення глобальної змінної Cypress.
Cypress-сценарії маршрутизації/адаптивності оновлені, додані бізнес-сценарії.
Їх запуск у цьому середовищі заблокований аварійним завершенням Cypress до виконання тестів
(Windows GPU process unusable, відмова доступу до профілю). Доступ до Chrome через UI не надано.
Тому візуальна працездатність карти, рух/масштабування і E2E потребують перевірки у браузері користувача.

## Скриншоти для звіту

1. Головна сторінка з деревом і лічильником API.
2. Реєстрація та приклад помилки підтвердження пароля.
3. Авторизований профіль і власна колекція.
4. Параметри посадки, розрахунок суми та крок підтвердження.
5. Повідомлення успіху і нова картка у колекції після reload.
6. Інтерактивна карта з popup та атрибуцією OpenStreetMap.
7. Фільтри, порожній результат та скидання.
8. DevTools Network із GET /trees і POST /trees (токен приховати).
9. Вивід ESLint, Vitest і build; E2E — після успішного локального запуску.
10. Мобільний вигляд карти та форми.

## Висновок

Статичний інтерфейс доповнено HTTP API, власними хуками, авторизацією та бізнес-логікою посадки.
Дані зберігаються на диску, статистика обчислюється за записами. Оплата та реальні посадки
не виконуються. Остаточна готовність до захисту потребує зазначеної браузерної перевірки.
